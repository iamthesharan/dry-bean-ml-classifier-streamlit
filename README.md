# Dry Bean Variety Classifier — ML Assignment 2

M.Tech (AIML), BITS Pilani WILP — Machine Learning, Assignment 2.

## a. Problem statement

Given 16 geometric/shape measurements extracted by image processing from
photographs of dry bean grains, classify each grain into one of **seven**
registered bean varieties: `BARBUNYA`, `BOMBAY`, `CALI`, `DERMASON`, `HOROZ`,
`SEKER`, `SIRA`. This is a **multi-class** classification problem. Five
classical ML algorithms — Logistic Regression, Decision Tree, KNN, Naive
Bayes and SVM — are trained on identical data splits and compared using the
same six evaluation metrics to see which generalizes best for this task.

## b. Dataset description

**[UCI Dry Bean Dataset](https://archive.ics.uci.edu/dataset/602/dry+bean+dataset)**
(Koklu & Ozkan, 2020), fetched programmatically via the `ucimlrepo` package
(`fetch_ucirepo(id=602)`).

- **Original size:** 13,611 instances × 16 features, 7 classes.
- **Features (16):** `Area`, `Perimeter`, `MajorAxisLength`, `MinorAxisLength`,
  `AspectRatio`, `Eccentricity`, `ConvexArea`, `EquivDiameter`, `Extent`,
  `Solidity`, `Roundness`, `Compactness`, `ShapeFactor1`, `ShapeFactor2`,
  `ShapeFactor3`, `ShapeFactor4` — all numeric, derived from grain contours.
- **Target:** `Class` (7 categories, listed above).
- **Sampling for this assignment:** a stratified random subsample of
  **3,000** instances was drawn from the full dataset (fixed `random_state=42`)
  to keep training — especially SVM probability calibration — fast on a
  laptop, while still comfortably exceeding the assignment's minimums
  (≥500 instances, ≥12 features). This was split **80/20** (stratified) into
  2,400 training rows and 600 test rows. The 600-row test split is saved as
  [`test_data.csv`](test_data.csv) and is what the Streamlit app scores.

## d. Models used

All five models were trained on the **same** 2,400-row training split and
evaluated on the **same** 600-row held-out test split (`test_data.csv`).
Every model is wrapped in a `scikit-learn` `Pipeline(StandardScaler → classifier)`
so preprocessing is identical and reproducible, and is persisted with `joblib`
so the Streamlit app can score new data without ever retraining.

| ML Model Name | Accuracy | AUC | Precision | Recall | F1 | MCC |
|---|---|---|---|---|---|---|
| Logistic Regression | 0.9250 | 0.9964 | 0.9390 | 0.9409 | 0.9397 | 0.9097 |
| Decision Tree | 0.9017 | 0.9442 | 0.9131 | 0.9125 | 0.9122 | 0.8814 |
| KNN | 0.9283 | 0.9924 | 0.9431 | 0.9433 | 0.9423 | 0.9138 |
| Naive Bayes | 0.9083 | 0.9944 | 0.9099 | 0.9188 | 0.9132 | 0.8899 |
| Support Vector Machine | 0.9283 | 0.9967 | 0.9421 | 0.9434 | 0.9425 | 0.9136 |

*(Precision / Recall / F1 are macro-averaged across the 7 classes; AUC is
macro-averaged one-vs-rest; MCC is the multiclass generalisation of Matthews
Correlation Coefficient. Regenerated by running `python train.py`; see
[`metrics_summary.csv`](metrics_summary.csv).)*

### Observations

| ML Model Name | Observation about model performance |
|---|---|
| Logistic Regression | Strong, well-balanced performance (92.5% accuracy, 0.9964 AUC) despite being a linear model — the 16 shape features must be fairly linearly separable per class after standardization. Fast to train and the most interpretable of the five. |
| Decision Tree | Lowest AUC (0.9442) and MCC (0.8814) of the five. A single tree's axis-aligned splits struggle to rank-order probabilities as smoothly as the other models, and `max_depth=10` trades a little accuracy for less overfitting; still respectable accuracy (90.2%) but clearly the weakest here. |
| KNN | Joint-best accuracy (92.8%) and best Precision (0.9431) and MCC (0.9138). With `k=7` and standardized features, local neighborhoods in this geometric feature space separate the bean varieties very well — but it is the slowest model to score at inference time since every prediction scans the training set. |
| Naive Bayes | Noticeably lower Precision/Recall/F1 (~0.91) than the top models even though its AUC (0.9944) is still high. Many of the 16 features (e.g. `Area`, `Perimeter`, `ConvexArea`, `EquivDiameter`) are highly correlated size measures, which violates Gaussian NB's feature-independence assumption and hurts its calibration and hard-label accuracy, even though it can still rank classes reasonably well. |
| Support Vector Machine | Best AUC (0.9967) and best F1 (0.9425) overall; essentially tied with KNN for best accuracy (92.8%). The RBF kernel captures non-linear class boundaries that the linear Logistic Regression cannot, without KNN's inference-time cost. |
| **Overall, Winner for your dataset?** | **Support Vector Machine** — highest AUC and F1, tied for highest accuracy. KNN is a very close second (actually edges SVM on Precision/MCC by <0.001); Logistic Regression is a strong, much cheaper third choice. Decision Tree and Naive Bayes trail because a single axis-aligned tree and the feature-independence assumption are both a poor fit for these correlated, continuous geometric features. |

## Running locally

```bash
pip install -r requirements.txt
streamlit run app.py
```

Then, in the app, either upload a CSV with the same 16 feature columns + `Class`
target column (e.g. re-upload `test_data.csv`), or tick "Use bundled
test_data.csv instead" to try it immediately.

## Reproducing training

`train.py` additionally needs the `ucimlrepo` package (only at training time,
not for the deployed app) to download the raw dataset:

```bash
pip install ucimlrepo
python train.py
```

This re-fetches the dataset, re-samples/re-splits it, retrains all five
models and overwrites `model/*.joblib`, `test_data.csv` and
`metrics_summary.csv`.

## Streamlit app features

- **CSV upload** of test data (or a one-click "use bundled sample" toggle).
- **Model selection dropdown** to inspect any of the five classifiers.
- **Evaluation metrics** (Accuracy, AUC, Precision, Recall, F1, MCC) for the
  selected model, plus a side-by-side comparison table for **all five**
  models on whatever data was uploaded.
- **Confusion matrix** (heatmap) and full **classification report** for the
  selected model.

All scoring loads the pre-trained `joblib` pipelines and calls `.predict`
/`.predict_proba` only — the app never calls `.fit()` on uploaded data.
